EMOTICORE — Project Report

AI-powered behavioral threat detection, running entirely in the browser. Complete record of what was built, the technologies and models used, the algorithms behind each feature, and the decisions that shaped them.

VERSION 1.0 JULY 2026 9 GIT COMMITS ~5,400 LINES 4 PAGES + PWA

01Executive overview

Emoticore is a personal browser demo that fuses a webcam and a microphone into one on-screen score — "Score affect before you call it a threat." The landing page states what the code actually computes. Three product surfaces run the analysis for real.

Everything is built under four deliberate constraints:

  • No backend. Every page is a self-contained static HTML file — no server, no database, no accounts.
  • No frameworks, no build step. Pure HTML5 / CSS3 / vanilla JavaScript. The files open directly in a browser.
  • On-device analysis. Video and audio never leave the machine. The single exception (optional speech transcription) is opt-in and labeled in the UI.
  • One design system. A "defense-tech mission control" visual identity shared across all pages.

  • Real in-browser ML: face detection, 68 facial landmarks, and 7-class expression classification on the user's webcam.
  • Live overlay: corner-bracket subject lock, landmark dots, per-subject labels; stable subject IDs via frame-to-frame IoU tracking.

voice.html — Voice emotion analysis

  • Record up to 15 s of microphone audio (codec-free PCM capture) or upload an audio file (MP3/WAV/M4A/OGG, first 30 s).
  • On-device prosody engine scores six emotions — Calm, Happy, Surprised, Nervous/Fearful, Angry, Sad — plus a 0–100 vocal stress index.
  • Outputs: dominant-emotion verdict in plain language, measured prosodic features (mean pitch, range, jitter, energy, rate, pauses), waveform envelope, WAV replay of the sample.
  • Last five analyses persist in localStorage; click any history entry to re-view. Rejects samples with under ~2 s of audible speech.

console.html — Operations Console (flagship)

  • Fusion pipeline: camera and voice analyzed simultaneously; facial threat and vocal stress merge into one live index, with transcript keyword hits adding a decaying boost. Mic denied → graceful face-only mode.
  • Session recording: telemetry sampled at 4 Hz into a live 120-second scrolling timeline chart with threshold bands, three plotted series, a dominant-emotion color strip, and a time grid.
  • Incident engine: threat held above ELEVATED for 1.5 s opens an incident — video-frame snapshot captured, live card with peak/duration/driver, severity escalation to HIGH, hysteresis close.
  • Session reports: end-of-session summary (avg/peak threat, % time elevated, affect distribution) with JSON and CSV export — generated locally as Blob downloads.
  • Settings drawer: face/voice fusion balance, both thresholds, editable threat lexicon, alert-sound toggle — persisted in localStorage.
  • Command palette: Ctrl+K, filterable, keyboard-navigable — sessions, toggles, exports, navigation.

04AI models & analysis engines

4.1 Facial pipeline — neural networks (demo.html, console.html)

ModelTaskOutput
tinyFaceDetectorFace detection (Tiny Face Detector, not YOLO)Bounding boxes + confidence; input 416 px, threshold 0.4
faceLandmark68TinyNetFacial landmarks68 landmark points per face
faceExpressionNetExpression classification7 classes: neutral, happy, sad, angry, fearful, disgusted, surprised (probabilities)

Models are fetched once from CDN, then run entirely locally at typically 10–25 inference FPS. Emotion values are EMA-smoothed (α = 0.25) before display.

4.2 Vocal pipeline — signal processing (voice.html, console.html)

  • Pitch (F0): normalized autocorrelation (overlap energy in the denominator, so longer lags are not penalized). The tracker keeps the first strong peak, which is the fundamental, instead of a later subharmonic. Search range 60–400 Hz, coefficient gated at 0.45, on a ~8 kHz decimated copy. Decimation cuts the ACF cost ~40× so a 15 s clip analyzes in well under a second.
  • Loudness: per-frame RMS → dB; jitter: frame-to-frame F0 delta / mean; rate: energy-peak (syllable-proxy) count per second; pauses: sub-threshold frame ratio; contour: linear-fit F0 slope.
  • Live vocal stress (console): a per-session baseline is calibrated from the speaker's first ~30 voiced frames (median F0 and median RMS); stress then measures deviation — pitch elevation + jitter + loudness spikes vs. that personal baseline.
  • Clip emotion estimate (voice page): extracted features feed six independent weighted scores, each clamped to 0–100. They are not forced to sum to 100%. A separate confidence uses how voiced the clip is and how far the top score sits above the second. The UI labels both as a heuristic.

4.3 Threat fusion (console.html)

facial_raw = 100 × min(1, angry×1.00 + fearful×0.85 + disgusted×0.50 + sad×0.20 + surprised×0.25)
fused = (faceW × facial_raw + voxW × vocal_stress) / (weights present) + lexicon_boost
threat_index ← threat_index + (fused − threat_index) × 0.12  // EMA smoothing

defaults: faceW = 0.65, voxW = 0.35 · lexicon_boost ≤ 45, decays ×0.988/frame
levels: LOW < 35 ≤ ELEVATED < 65 ≤ HIGH (all user-tunable)

4.4 Incident engine (console.html)

open:  threat ≥ ELEVATED sustained ≥ 1.5 s → capture snapshot, open card
close: threat < ELEVATED − 5 sustained ≥ 2.0 s  // hysteresis prevents flicker
escalate: peak ≥ HIGH → severity HIGH

4.5 Subject tracking (demo.html, console.html)

Greedy intersection-over-union matching of face boxes between consecutive frames (IoU > 0.2, best-pair-first); unmatched detections get new IDs; tracks expire after 1.2 s unseen. Result: SUBJ_01/SUBJ_02 labels stay attached to the same person on both the camera demo and the operations console. The console's largest face is still the one that feeds the score, but the id does not reset when someone else becomes larger.

06Privacy architecture

  • All video inference and all audio DSP run on-device; no frame or sample is ever transmitted. Every page states this in the UI.
  • The one exception is transcription: the Web Speech API routes audio through the browser vendor's speech service. It is off by default, opt-in per session, and labeled as cloud-routed at the moment of enabling.
  • Cameras and microphones are released on stop and on page exit (pagehide).
  • Exports (JSON/CSV) are generated locally as Blob downloads — no upload endpoint exists.

08Honest limitations

Demo-grade accuracy. The face models are open, lightweight networks. The site does not claim a measured accuracy, a certification, or a customer. The vocal stress and voice-emotion scores are transparent DSP heuristics (prosody distinguishes arousal well, valence roughly), labeled as heuristics rather than a clinical measure. A production system would need serious models, validation datasets, and a legal/compliance review — emotion recognition is regulated in some jurisdictions (e.g. the EU AI Act).
  • Session data lives in memory; closing the tab discards an unexported session.
  • Transcription requires Chrome/Edge and an internet connection; Firefox shows "N/A".
  • Camera/mic on file:// work in most Chromium browsers, but localhost/https (VS Code Live Server) is the reliable path — and required for the PWA/service worker.
  • First run needs internet for the ~4 MB engine + models (cached afterward).
